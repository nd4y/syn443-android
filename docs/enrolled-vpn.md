# Enrolled native VPN

The account path feeds the real controller and isolated native host through `RuntimePolicies`. It selects either the operator journal or the enrolled journal; it never copies activation history between them. While any login, provisioning, reauthentication or retirement state is active, missing/invalid account policy blocks configuration use and local imports. The original operator configuration remains stored for a later explicit signed-out Connect.

Login and assignment receipt leave VPN Off. An explicit Connect may start with a worker-validated candidate, but the service must durably begin its activation before reading a candidate configuration. A first account assignment starts without an unsigned baseline, after retiring any old owner and admitting the restart budget. Baseline checks for subsequent assignments, bounded candidate timeout, native startup, route checks and last-known-good rollback use the existing TUN supervisor. The published lease is scoped to the account, receipt and activation and expires on conservative monotonic time. A retired or expired native reader cannot be revived by renewal. Policy publication wakes reconciliation, avoiding long blocked-state polling after an asynchronous transition.

Established session/policy requests capture a physical non-VPN Network for DNS and every socket. Periodic fetch is bounded to the signed refresh interval within 30-300 seconds; explicit refresh has a five-second admission floor. No refresh runs over an applying candidate. A transport/server outage retains an authorized offline lease; an authenticated access denial withdraws the view and requires reauthentication. No local configuration fallback follows that denial.

Logout first changes durable intent and clears the runtime permit. Key retirement acknowledgement waits on a bounded worker for both native process absence and owner-lock release. A frozen host is handled by the existing supervisor; a timeout remains visibly incomplete, without claiming SignedOut. Managed overlays remain rejected until account-specific native credentials and their retirement are implemented.

`EnrollmentDriver` lives only in the test APK and delegates ordinary instrumentation to `AndroidJUnitRunner`. An explicit fixture argument selects the emulator-only enrollment flow. The disposable-emulator harness uses an ephemeral loopback TLS issuer/API with generated RSA/EC keys, checks PKCE and DPoP signatures, and returns signed key-bound policies. It invokes the same own-UID controller calls as the callback Activity. Five additional cases require real TUN traffic, controller-death/offline-cache recovery, failed replacement rollback, confirmed-denial blocking and logout with a frozen native host. It is not an external-browser UI test and does not contact production services.

Acceptance requires exact-head Actions on API 29/35/37 and separately scoped physical verification. These source changes alone do not establish physical enrollment, Wi-Fi/LTE handover, restricted-LTE routing, battery, natural Doze or endurance acceptance.
