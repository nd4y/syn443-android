# Identity lifecycle and interrupted enrollment

The server accepting a request and the client receiving its response are different events. An enrollment can consume a device slot even if the phone loses the response, closes the browser, crashes or logs out. A client must not create a new key and silently abandon every earlier registration. It also must not retain logged-out private credentials merely to perform future cleanup.

## Owner-authenticated cleanup

`POST /v1/identity/devices/revoke` accepts a fresh pinned OIDC/DPoP identity, `requestId` and one to sixteen unique public-key thumbprints. The new proof key must match `cnf.jkt`; the nonce, method, URI, time, replay and exact raw-body hash checks remain required. The caller proves ownership through the issuer/subject pair, not a supplied owner ID, email, device ID or old key. A lost old key is not required.

The transaction locks that account, revokes only matching registrations owned by it, and retires their device sessions. Unknown and foreign thumbprints return the same204 response without revealing or changing foreign registrations. A denied/expired assignment may still clean up its own devices but cannot receive a session or configuration. Fresh-proof retries with the same request ID/body are idempotent for three minutes; changed bodies conflict. This endpoint is neither an enrollment grant nor an admin session.

Identity nonce challenges expire after three minutes. At most32 live challenge keys per account are admitted; expiration cleanup uses an index. This bounds retries that abandon a browser/key before completing enrollment. All paths share the same account lock with quota checks and device-session revocation. Runtime API privileges cannot approve/sign/revive a device.

## Android integration contract

The protocol core, protected Android journal, Keystore adapter and bounded transport exist. The registration-only controller/UI pilot below implements part of these rules; policy handoff and full interactive acceptance remain pending:

1. One controller owns a durable auth generation and single-use pending transaction. Persist a reserved key alias and public thumbprint before generating/using it. Browser state, nonce and PKCE verifier remain protected; no password is handled by the client.
2. Before sending enrollment, persist its request ID/body and mark its public thumbprint as potentially registered. A process restart retries the same request/key within the idempotency window or performs owner cleanup after fresh login. A timeout is not proof that no device was created.
3. Cancel/Logout invalidate the auth generation before later effects can commit, cancel the active raw socket and keep the bounded pool instance. No callback, queued DNS result, crypto completion or stale configuration may bypass that fence. Pre-existing thread interruption remains cancellation.
4. Logout stops VPN intent and retires the native owner, removes local sessions/assigned policy/private credentials, and attempts a proof-bound revoke when online. If the result is unknown or offline, keep only a bounded public-thumbprint tombstone. Do not claim server revocation. A subsequent fresh OIDC identity drains owned tombstones through the cleanup endpoint before trying a new enrollment, without retaining the logged-out signing key or token. Never silently revoke other devices to satisfy a quota.
5. Identity proof validation and policy activation are separate effects. A verified credential or immutable signed bundle may be cached only for its current auth generation; network observations and activation use the current VPN/network/config generations. Stop cannot become an automatic Connect. No network/key operation runs on the UI/Binder thread, and no unbounded pool is recreated on retry/logout.
6. For an existing local configuration, retain it encrypted on-device. An enrollment binding must be a separately verified delivery kind using pretrusted roots and a new device scope. Keep its policy journal separate from the earlier local-management ledger. Do not import an assigned profile into an unmanaged slot as an intermediate step: a crash there would bypass its signed lease. A bound-but-incomplete enrollment remains blocked until a valid candidate is present. A confirmed Logout may restore the preceding local mode only after Stop; ordinary fresh clients have no unsigned fallback.
7. Managed overlay identities/caches need explicit enrollment namespaces and cleanup after owner retirement. A synthetic direct-path pilot does not prove that NetBird/provider secret cleanup is complete. Do not advertise unsupported managed engine lifecycle capabilities.
8. Bootstrap roots and issuer/API origins come from a trusted operator/signed bootstrap, never an arbitrary API response. The pilot may use an operator-only debug staging file; release invitation/auth bootstrapping still needs its own acceptance. Deep-link handling is exact `syn443://oauth/callback`, state/issuer/nonce bound, single-use and boot/elapsed-deadline checked. Browser launch does not prove an interactive form/callback flow passed.

Required regression cases include a response lost after server commit, concurrent cancel and enrollment, cold restart before/after policy binding, reused callback/code, changed boot/clock, missing/invalidated key, stale crypto/DNS completion, cleanup with a new key, foreign thumbprints, disabled assignment, conflicting retry bodies, full challenge/worker queues, and logout while offline. Physical Wi-Fi evidence and real external-browser interaction remain separate from JVM/HTTP fixtures and from the excluded LTE/Doze/battery gates.

## Signed key and initial time binding

New enrollment publications use payload version2, required capability `policy.keybound.v2`, and a signed `keyThumbprint` alongside `targetDevice`. The publisher derives it from the independently authenticated immutable device key; owner templates cannot supply it. Clients call the bound verifier with a thumbprint computed from their own Keystore public key, not a delivery field. A valid signature for a delivery-selected device ID is insufficient. Version1 remains only for existing local-management fixtures/compatibility and is rejected by enrollment-bound verification. The locked schema, Go/Kotlin tests and public Go-issued signature fixture enforce this distinction. Do not activate a version1 policy through a new identity binding.

At first enrollment, the trusted-time floor also includes fresh issuer time from the verified HTTPS token response. A delivery-only clock cannot rewind below that independent identity time. Keep monotonic/boot anchors and bounded request-duration uncertainty; validity/lease checks use a conservative time bound while DPoP iat must remain within the server's accepted window. Persist these anchors with the binding and never extend a lease because the token/session was refreshed. The browser/coordinator integration must implement and test this; it is not implied by the current pure protocol tests.

## Public recovery intent and account switching

`LoginRecovery` now models a bounded nonsecret recovery intent separately from the protected credential payload. It reserves a unique key alias and generation before key creation, binds the protected payload digest, consumes a callback before exchange and marks a public key as potentially registered before enrollment dispatch. Enrollment/cleanup/refresh retries retain exact operation bodies and the original three-minute retry clock. Registered sessions resume with the same device/key; a changed boot asks for fresh trusted time, without silently registering a new device. Cached policy identity is independent of refresh and its lease is never extended by session rotation.

Cancel advances the generation immediately and removes active credential references. The retiring state retains only owned key aliases and bounded public registration tombstones. Signout is acknowledged only after native ownership is released, protected state is erased and key deletion is confirmed. Android key creation must recheck the generation while holding its Keystore-operation lock: a queued old creation cannot run after cleanup has already deleted an absent alias. Network/key operations remain outside the intent lock. These are model invariants; Android persistence/coordinator/browser wiring and physical cancellation races remain pending.

A cleanup tombstone includes a nonsecret owner tag derived from the configured service identity, verified issuer and verified subject, plus the old public-key thumbprint. It holds no user/device credential and is never telemetry. Fresh login drains only matching owner tags. Because the server deliberately returns the same204 for foreign/unknown keys, a different account must not silently discard the prior account's tombstones. Approved signing-root changes do not change this owner tag. At most32 tombstones are retained and each cleanup batch has at most16 keys; fresh authentication for cleanup remains possible at capacity, while new enrollment is blocked until capacity is available. No foreign registration is silently removed to satisfy a quota.

The model has positive/negative/boundary tests for account switching, lost replies, restart/boot, stale callbacks and acknowledgements, exact retry deadlines, policy preservation, protected-payload/key mismatch, capacity, serialization and malformed recovery metadata. A pure intent model is not an interactive-login acceptance.

## Android protected journal

`LoginJournal` stores bounded public intent and AES-GCM ciphertext in separate AtomicFiles under `noBackupFilesDir`. The dedicated Android Keystore root stays on-device. Auth generation, trusted-bootstrap fingerprint and journal namespace are authenticated associated data. The public intent contains a digest of the exact ciphertext. Crypto runs outside the intent lock and is rejected on UI/Binder threads; cancellation persists its newer generation without waiting for a Keystore operation. Compare-and-swap rejects a late encrypted result. Public metadata is committed before its ciphertext, and readback admits the pair only if both match. A crash between writes produces a recoverable blocked state, never an old credential or unsigned configuration fallback. Corrupt/missing intent with remaining protected data is also blocked.

Cancellation clears credential references and erases ciphertext. A retiring state can retry erasure after interruption; Signout cannot be acknowledged while protected files remain. The journal does not log exception causes, tokens or paths. Payloads and metadata are bounded at64KiB. Policy envelopes use a separate encrypted assignment record with a 2MiB bound; the credential record remains64KiB. See [assigned-policy-handoff.md](assigned-policy-handoff.md).

`DeviceKey.createIfCurrent` rechecks the public generation while holding the Keystore-operation lock. Deletion serializes after an already admitted creation; a queued stale creation after deletion does nothing. No intent-lock holder may wait for this Keystore lock. The Android tests exercise the actual Keystore race, process-style journal reopen, callback single use, delayed encryption after cancellation, interrupted file pairs, authenticated-data mismatch, tampering, oversized/missing/corrupt files, AtomicFile backup recovery and worker-thread boundaries. They use isolated synthetic namespaces and delete only their own files/keys. The controller pilot below builds on these primitives; real interactive login, managed policy handoff and managed overlay cleanup remain pending gates.

## Registration-only controller pilot

`LoginController` now connects protected payloads to the protocol through a single bounded worker in the controller process. An operator-only debug staging file supplies trusted bootstrap roots and endpoints. Its validated public trust material is stored privately under no-backup storage; tokens/verifiers use only the protected journal. There is no arbitrary endpoint field in the end-user UI. The dark UI opens the configured external browser and handles only the exact `syn443://oauth/callback`; codes are neither logged nor persisted. Valid errors consume the transaction, invalid callbacks do not. Callback processing never sends a VPN Connect command.

The pilot starts only with VPN Off and no existing managed binding. Once an auth intent is active, legacy Connect is blocked. Registered sessions resume with their original key/device; they fetch a signed assignment and may reach `POLICY_CACHED`, but cannot activate the assigned profile yet. This deliberate boundary prevents a new identity profile from passing through an unsigned local-config slot. Browser interaction, signed-policy handoff, managed refresh on a physical Network, automatic retry admission and managed overlay namespaces still need their own implementation/acceptance.

Cancel immediately invalidates an in-memory command epoch in addition to the durable auth generation, closes the active socket scope, clears queued commands and erases protected data. This also fences work when an intent write fails. Storage failure is not reported as successful durable Logout; a queued owned-key deletion prevents reuse of a stale private key when possible. A registered session still present in worker memory gets one bounded proof-bound online revoke attempt. Only a validated success removes its own public tombstone; unknown/offline outcomes retain it for fresh owner cleanup. Private keys are deleted after the attempt. Existing local VPN configuration is retained.

`LoginPayload` admits one phase-specific pending transaction, user credential or device session, bound to the public intent's generation/key/owner/device/session revision and trusted bootstrap. Its canonical encoding rejects omitted fields and type coercion. Android controller tests use isolated synthetic namespaces and real Keystore/RS256/ES256 verification. They exercise successful registration, same-device restart, exact retry after a lost enrollment reply, cancellation after a simulated server commit, fresh-owner orphan cleanup and online revoke. Separate emulator tests use the actual provider and callback Activity for browser reservation, controller death, invalid/error callback handling and unchanged VPN intent. The test transport factory has no IPC route and is limited to debug disposable emulators. These are not real external-browser or deployed control-plane evidence.

The next cache stage connects registration to signed policy receipt and exact session refresh while VPN is Off. Its separate encrypted assignment journal, two-write receipt fence and remaining native handoff gates are described in [assigned-policy-handoff.md](assigned-policy-handoff.md).
